How to assign a rule to a CDE

Assigning a data quality rule to a CDE creates a rule allocation record. Each allocation links one rule to one CDE and specifies how frequently the check runs and what the acceptable threshold (bumper value) is.

Add an allocation

  1. 1
    Expand the hierarchy until the target CDE row is visible.
  2. 2
    Click the + icon on the right side of the CDE row. The allocation panel slides open.
    This button is only visible when your steward identity is set.
  3. 3
    Select a Rule from the dropdown.
    By default, the Filter is on and the list shows only rules relevant to this data set: rules with no CDS prefix (generic rules) and rules prefixed with the name of the current data set. The hint below the dropdown shows how many rules are visible and why.
    If the rule you need is not listed, click the Filter pill in the top-right of the Rule section to turn the filter off. The dropdown then shows all active rules regardless of naming. The hint changes to “Showing all available rules”.
    The filter resets to on each time you open a new allocation panel.
  4. 4
    Select the Quality Dimension this allocation measures (for example, Completeness, Accuracy, Timeliness).
  5. 5
    Set the Frequency and, if applicable, the Bumper Value.
    The bumper value is the threshold used by the rule (for example, a maximum acceptable null rate). Leave it blank if no threshold applies.
  6. 6
    Click Add. The allocation is saved and the CDE row updates to show the new rule and metric counts. The CDE row now shows a chevron button to expand and view all allocations.

SQL validation notices

After you select a rule, the panel automatically checks the rule’s SQL against the standards required by the DQ execution engine. If any issues are detected, notices appear below the Bumper value field. Saving is not blocked — proceeding is at the data steward’s discretion.

LevelWhat it means
CRITICAL The rule SQL has a structural problem that will produce invalid SQL when the engine appends its snapshot filter at run time. Allocating a rule with a CRITICAL notice will cause the executed query to fail.
SEVERE The rule SQL violates a coding standard. The query may run but could return incorrect results or cause runtime errors in Athena.

CRITICAL checks

  • Rule SQL has no WHERE clause — the engine appends AND <snapshot_filter> to the SQL, which requires a WHERE clause to already be present.
  • Rule SQL ends with a semicolon — the engine appends the snapshot filter after the final character.
  • Sample SQL contains a WHERE clause — the engine appends WHERE <snapshot_filter> to the sample SQL, which must not already contain one.
  • Sample SQL ends with a semicolon.

SEVERE checks

  • Rule SQL uses CAST() — TRY_CAST() is required to avoid runtime data conversion errors.
  • Rule SQL uses a bare IS NULL or = '' check — NULLIF(TRIM(field), '') IS NULL is required to handle NULL, empty, and whitespace-only values correctly.
  • Rule SQL is missing the {SOURCE_DATABASE_NAME} placeholder.
  • Rule SQL is missing the {SOURCE_TABLE_NAME} placeholder.
  • Rule SQL is missing the {SOURCE_FIELD_NAME} placeholder.
  • Rule has no SQL code defined.
When notices appear, a message at the foot of the block reads “Review and correct this rule in the Rules Explorer page.” Navigate to the Rules Explorer, find the rule by name, and edit its SQL to fix the issue before completing the allocation.

View allocations on a CDE

When a CDE has at least one rule allocated, a chevron button appears on the right of the CDE row. Click it to expand the allocations list. Each allocation shows:

ColumnWhat it shows
Rule nameThe name of the data quality rule.
DimensionThe quality dimension measured by this allocation.
FrequencyHow often the check is run.
Bumper valueThe threshold. Shown in amber if set; -- if not.
SQLButtons to open the full SQL and the sample SQL for this allocation in the SQL viewer.

Edit or remove an allocation

  1. 1
    Expand the CDE row to show the allocations list.
  2. 2
    Click the pencil icon on the allocation row to edit it, or the eye-off icon to retire it.
    Retiring an allocation removes it from active counts but does not delete the record. Retired allocations appear faded in the expanded list.
  3. 3
    If editing: update the fields in the panel and click Save.
If the CDE is missing a snapshot filter, its allocation rows show a red border and the SQL viewer buttons are disabled. Edit the CDE and add a snapshot filter to enable SQL generation.
