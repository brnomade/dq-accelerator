What is a snapshot filter?

Understanding what a snapshot filter is and how to identify the right value for a CDE before saving it.

The problem snapshot filters solve

Many source tables don't hold just one current version of the data — they accumulate multiple loads over time: daily extracts, monthly snapshots, SCD history, and so on. Without a filter, a Data Quality rule would evaluate every row in the table, mixing current and historical records together.

A snapshot filter tells a DQ rule which slice of that history to evaluate for a given CDE, so the rule measures quality on the record set that actually represents “the data as of a point in time” rather than mixing in outdated or duplicate rows.

Think of it as answering the question: “Out of everything sitting in this table, which rows count as ‘the current picture’ for this CDE?”

Why it matters

Without a snapshot filter, a DQ rule can be technically correct but practically misleading. For example, a rule might flag a field as “100% populated” only because old snapshots happen to have it filled, while the latest load doesn’t. The rule passes — but the data quality problem goes undetected.

This is why the snapshot filter is a required field on every CDE. A CDE without one cannot have SQL generated for its rules.

How to identify the right snapshot filter

  1. 1
    Check the table for a date, load-id, version, or partition column that distinguishes one snapshot from another.
    Common examples: snapshot_date, load_id, batch_date, partition_dt, is_current.
  2. 2
    Confirm which value represents the version the business considers authoritative for that CDE.
    For example: the latest date, a specific partition key, or a status flag such as is_current = true.
  3. 3
    Write the filter as a SQL WHERE clause fragment and enter it into the Snapshot Filter field.
    Example: snapshot_date = '{snapshot}' or is_current = true. The DQ engine substitutes the {snapshot} placeholder at run time.

When you are not sure

If the right filter is not documented in the source metadata or is not obvious from the table structure, do not guess. This is a question for the data engineering team — they own the pipeline logic and know how snapshots are generated and maintained.

Rule of thumb: if you cannot point to the specific column and value that isolates “today’s” data in under a minute, confirm it with the data engineer responsible for that source before finalising the CDE.
A CDE saved with an incorrect snapshot filter will pass validation but produce misleading DQ results. It is better to leave the CDE incomplete and return to it once the correct filter is confirmed.
