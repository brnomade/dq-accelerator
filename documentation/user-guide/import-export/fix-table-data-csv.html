How to fix table data using CSV import

Use this feature when you need to correct data problems in a specific table — such as duplicate primary keys, incorrect values, or broken references — without reimporting the entire dataset. You export the affected table as a CSV, fix the rows externally, and reimport just that table to replace its contents entirely.

Master steward only. The Single Table CSV tab is only visible when you are operating as the master steward. Regular stewards do not have access to this feature.
Destructive operation. The table is completely replaced by the contents of the uploaded CSV. All current rows in that table are removed and replaced by the rows in the file. This cannot be undone without a prior backup.

Before you start

Export a full backup before making any changes. This gives you a recovery point if the import produces unexpected results. See How to export a full backup.

Step 1 — Export the table you want to fix

  1. 1
    Click Export in the left sidebar.
  2. 2
    Under Backup export, click Export backup to download the full ZIP.
    The ZIP contains one CSV file per table, each named after the table (e.g. critical_data_element.csv).
  3. 3
    Extract the ZIP and locate the CSV file for the table you need to fix.

Step 2 — Edit the CSV

  1. 1
    Open the CSV in a spreadsheet application (Excel, LibreOffice, or a text editor).
  2. 2
    Make the corrections you need — fix values, remove duplicate rows, correct primary key values, or update foreign key references.
    Do not rename or remove the header row. Do not rename the file. The column headers and filename are used by the import to identify the table.
  3. 3
    Save the file as CSV, keeping the original filename (e.g. critical_data_element.csv).
    If your spreadsheet application warns about losing formatting, confirm you want to keep the CSV format.

Step 3 — Import the corrected CSV

  1. 1
    Click Import in the left sidebar.
  2. 2
    Click the Single Table CSV tab.
  3. 3
    Drop your CSV file onto the drop zone, or click the zone to open the file picker.
  4. 4
    The application detects the table from the filename and displays a preview panel showing the table name, the current row count, and the incoming row count.
    If the filename is not recognised, you will see an error. Rename the file to match the table name exactly (e.g. critical_data_element.csv) and try again.
  5. 5
    Review any FK Warnings shown in the panel. Each warning line has a Show rows button. Click it to expand a full table of the affected records, with the broken foreign key column highlighted in amber so you can see the exact value that is missing or will become orphaned. Warnings do not block the import — review them and decide whether to proceed.
    Two types of warning exist: outbound (an incoming row references a value in another table that does not exist — e.g. a critical_data_set_id that is not in your database) and inbound (an existing row in another table will lose its reference because the record it points to is being removed by the replace). Click Collapse to hide the row detail again.
  6. 6
    Click Replace Table to confirm. The table is replaced immediately and your changes are saved to local storage.

Fixing problems that span multiple tables

If a fix requires changes to more than one table — for example, correcting a primary key value in a parent table and updating the matching foreign key values in a child table — import the tables in parent-first order:

  1. 1
    Import the parent table first (e.g. critical_data_set.csv).
  2. 2
    Import the child table second (e.g. critical_data_element.csv).
    This order ensures the FK validation in step 3 can resolve references correctly after each replace.
Soft-deleted records: the backup export excludes soft-deleted records by default. If you reimport a CSV exported without soft-deleted rows, those rows are permanently removed from the table. Export with the soft-delete toggle enabled if you need to preserve retired records.
