How to merge a steward delta

When a steward sends you their delta file, you import it on your master copy, review any conflicts and proposed new records, then apply the merge. A merge report is downloaded automatically as an audit trail.

You must be designated as master steward before merging. Open Settings (top-right cog icon) and confirm that Designate as master steward is enabled. The Delta import tab is only available in master mode.
  1. 1
    Click Import in the left sidebar.
  2. 2
    Select the Delta import tab at the top of the Import screen.
  3. 3
    Drop the steward’s delta file onto the drop zone, or click Browse to select it.
    The file name will look like dq_delta_[steward name]_[timestamp].json.
  4. 4
    Review the Delta import summary card. It shows the steward name, the base version their delta was built against, the export timestamp, and the counts of inserts, auto-updates, and conflicts.
  5. 5
    If a Version mismatch warning appears, read it carefully. It means the steward’s delta was built against an older version of the master than you currently hold. Conflict detection may flag phantom conflicts. You can still proceed, but review conflicts and inserts with extra care.
  6. 6
    Resolve each conflict card by clicking Keep master or Accept steward. Conflicts appear in amber and must all be resolved before you can apply.
    Each card shows a side-by-side diff of the master value and the steward’s proposed value. Use Show all fields to see the full record if needed.
  7. 7
    Review the Inserts section, which appears below the conflict cards.
    All proposed new records are grouped by table. The section header shows how many are currently selected out of the total proposed (for example: Inserts — 517 of 517 selected). By default every insert is accepted.
  8. 8
    To accept all inserts without reviewing them individually, leave the section as-is and proceed to step 11. To review, continue with steps 9 and 10.
  9. 9
    Click a table group name (for example stewardship) to expand it and see the individual records. Each row has a checkbox: ticked means the record will be inserted, unticked means it will be skipped.
    Click Expand on any row to see all field values for that record before deciding.
  10. 10
    Use Accept all or Reject all on a table group to toggle the whole group at once. Use the global Accept all / Reject all buttons in the section header to toggle every insert across all tables.
  11. 11
    Once all conflicts are resolved, click Apply merge and download report.
    Only inserts with a ticked checkbox are added to the master data. Unticked rows are skipped entirely.
  12. 12
    A merge report file (dq_merge_report_[timestamp].json) downloads automatically. Keep it as an audit record. It contains the conflict resolutions, the insert counts accepted and rejected per table, and the PK remapping table.
  13. 13
    After the merge, export a new Master JSON from the Export screen and distribute it to your stewards so they can refresh their base version.
Auto-updates (shown in the summary card) are applied automatically without review. These are records the steward changed that the master has not touched since the shared baseline — there is no conflict, so no decision is needed.
