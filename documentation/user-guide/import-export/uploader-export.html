How to produce a DQ engine uploader export

The Uploader export packages the dataset as a ZIP of CSV files ready for the DQ engine. Before generating the file, the tool checks every rule allocation for validity and shows a review screen listing any failed allocations. Failed allocations are excluded by default to prevent the engine receiving malformed SQL definitions. The Master Steward can override individual exclusions to accept the risk and force-include them.

MASTER STEWARD only — The Uploader tab is only visible to the Master Steward. You must have identified yourself as the Master Steward to access it.

Step 1 — Open the Uploader tab

  1. 1
    In the sidebar, click Export.
    The Export page opens on the Master tab by default.
  2. 2
    Click the Uploader tab.
  3. 3
    Choose whether to include soft-deleted records using the Include soft-deleted records toggle.
    Default is off (live records only). Soft-deleted allocations bypass validation and are included when the toggle is on.
  4. 4
    Click Export for Uploader.
    The tool analyses all rule allocations and transitions to the review screen.

Step 2 — Review the failed allocations

  1. 5
    The headline shows how many allocations were evaluated and how many failed.
    If no allocations failed, a green confirmation is shown and you can export immediately.
  2. 6
    Failed allocations are displayed in a table grouped by Agency and CDS. Click any Agency or CDS header to collapse or expand that group.
  3. 7
    Each row shows one failed allocation with six check columns. A green tick means the check passed; a red cross means it failed.
    ColumnWhat it checks
    DBSource database name is present, not a placeholder, and contains no spaces
    TableSource table name is present, not a placeholder, and contains no spaces
    FieldSource field name is present, not a placeholder, and contains no spaces
    SQLRule SQL code is present and non-empty
    PHAll three source tokens ({SOURCE_DATABASE_NAME}, {SOURCE_TABLE_NAME}, {SOURCE_FIELD_NAME}) appear in the SQL
    BalSingle quotes, double quotes, and parentheses are balanced in the SQL
    Hover over a column header for a full description. Placeholder values (TBD, TBC, To Be Confirmed) and values containing spaces are treated as missing for the DB, Table, and Field checks.

Step 3 — Override exclusions (optional)

  1. 8
    To include a failed allocation despite its failures, tick the Include? checkbox on that row.
    This is a deliberate accept-risk action. The allocation will be included in the ZIP but the receipt will document that it was manually included with known failures. This does not fix the underlying data issue.
  2. 9
    To include all failed allocations within an Agency or CDS at once, tick Select all on the Agency or CDS header row.
    Individual checkboxes can still be changed after a bulk selection.
  3. 10
    The summary bar at the bottom of the page shows the live count: how many are still excluded, how many have been overridden to include.

Step 4 — Fix exclusions instead of overriding (recommended)

  1. 11
    To fix the underlying data rather than override, click Cancel to return to the Uploader tab settings.
  2. 12
    Navigate to the relevant screen to make corrections:
    • DB / Table / Field failures: open the CDE record and fill in the source fields.
    • SQL / PH / Bal failures: open the Rule record and correct the SQL template.
    Then return to Export and repeat from Step 1.

Step 5 — Confirm and download

  1. 13
    Click the confirm button when satisfied with the review.
    • Export ZIP — when no allocations remain excluded.
    • Export ZIP + receipt — when some allocations are still excluded or were overridden.
  2. 14
    The ZIP file downloads first, then the receipt (when applicable). Both share the same timestamp: dq_uploader_YYYYMMDDHHMMSS.zip and dq_uploader_receipt_YYYYMMDDHHMMSS.json.
    The tab returns to the settings view after the download completes. Override selections are cleared.

About the receipt

The receipt is a JSON file produced when any allocations were excluded or manually overridden. It contains two sections:

  • excluded_allocations — allocations that failed checks and were not overridden; absent from the ZIP.
  • overridden_allocations — allocations that failed checks but were manually included; present in the ZIP with known failures noted.

Share this file with field stewards to communicate which rules or CDEs need attention before the next uploader export cycle.

The uploader export does not store any validation status in the dataset. The validity check runs fresh at export time from current field values. Override selections are session-only and are not remembered between export runs. Stewards can leave rules or CDEs partially built indefinitely without affecting the working dataset.
