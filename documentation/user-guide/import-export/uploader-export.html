User Guide / Import & Export

How to produce a DQ engine uploader export

The Uploader export packages the dataset as a ZIP of CSV files ready for the DQ engine. Before generating the file, the tool checks every rule allocation for validity and shows a review screen listing any allocations that will be excluded. This ensures the engine never receives a malformed SQL definition.

MASTER STEWARD only — The Uploader tab is only visible to the Master Steward. You must have identified yourself as the Master Steward to access it.

Step 1 — Open the Uploader tab

  1. 1
    In the sidebar, click Export.
    The Export page opens on the Master tab by default.
  2. 2
    Click the Uploader tab.
  3. 3
    Choose whether to include soft-deleted records using the Include soft-deleted records toggle.
    When off (default), only live records are included. Soft-deleted allocations are excluded from the ZIP regardless of this setting even when the toggle is on, unless they pass validation.
  4. 4
    Click Export for Uploader.
    The tool analyses all rule allocations against the validity criteria and transitions to the review screen.

Step 2 — Read the review screen

  1. 5
    The headline shows how many allocations will be included and how many are excluded.
    Example: 42 of 51 Rule Allocations will be included. 9 excluded.
  2. 6
    If any allocations are excluded, the Excluded section is expanded by default. Each entry shows the Data Set name, field name, and rule name, followed by the specific reason(s) for exclusion.
  3. 7
    Click Included (N) to expand the list of allocations that will be exported. This section is collapsed by default.

What causes an allocation to be excluded

An allocation is excluded when any of the following are true:

  • The linked rule has no SQL code defined.
  • The linked rule record cannot be found.
  • The linked Critical Data Element cannot be found.
  • The CDE is missing source_database_name.
  • The CDE is missing source_table_name.
  • The CDE is missing source_field_name.
  • The rule SQL is missing a required placeholder ({SOURCE_DATABASE_NAME}, {SOURCE_TABLE_NAME}, or {SOURCE_FIELD_NAME}).
  • The SQL is empty after substitution.
  • The SQL has unbalanced single quotes, double quotes, or parentheses.

Step 3 — Fix exclusions (if any)

  1. 8
    If you want to fix an excluded allocation before exporting, click Cancel to return to the Uploader tab settings.
    The toggle state is preserved.
  2. 9
    Navigate to the relevant screen (Rules Explorer to fix SQL, Data and Stewardship to fill in missing CDE source fields), make the corrections, then return to the Export page and repeat from Step 1.

Step 4 — Confirm and download

  1. 10
    When you are satisfied with the review, click the confirm button.
    • Export ZIP — when no allocations were excluded.
    • Export ZIP + receipt — when some allocations were excluded.
  2. 11
    The ZIP file is downloaded first, then the receipt (if exclusions exist). Both files share the same timestamp: dq_uploader_YYYYMMDDHHMMSS.zip and dq_uploader_receipt_YYYYMMDDHHMMSS.json.
    The tab returns to the settings view after the download completes.

About the exclusion receipt

The receipt is a JSON file listing every excluded allocation with its CDE source fields (source_database_name, source_table_name, source_field_name, data_element_definition), the rule name, and the specific reasons for exclusion. Share this file with field stewards to communicate which rules or CDEs need attention before the next uploader export cycle.

The uploader export does not store any validation status in the dataset. The validity check runs fresh at export time from current field values. Stewards can leave rules or CDEs partially built indefinitely without affecting the working dataset.
