How to identify which CDS a field belongs to

Each field row in the Profiling page shows a CDS badge when the field is registered as a Critical Data Element. Hovering over the badge tells you which Agency and Critical Data Set the field belongs to, so you can navigate directly to the right CDS in the Rule Generator without searching.

Reading the CDS context

  1. 1
    Click Profiling in the left sidebar and expand a table by clicking its header row.
  2. 2
    Look at the field rows. Each row has an origin badge on the left: CDE, SQL, or CDE+SQL.
    SQL-only fields are not registered as Critical Data Elements and therefore have no CDS association. Only CDE and CDE+SQL rows carry CDS context.
  3. 3
    Hover over the CDE or CDE+SQL badge. A tooltip appears listing each Critical Data Set the field belongs to, one per line, in the format:
    Agency name / CDS name
    A field that appears in more than one CDS shows all of them in the tooltip, one line each.
  4. 4
    Note the Agency and CDS name shown in the tooltip. Go to the Rule Generator page and select that Agency and CDS to find the field and generate or review rules for it.
The CDS badge does not indicate how many rules the field has or whether it has been profiled. Use the rules count column and the green tick for that information. The badge is purely a navigation aid connecting the Profiling page to the Rule Generator.
