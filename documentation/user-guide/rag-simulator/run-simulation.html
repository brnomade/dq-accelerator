How to run a RAG simulation

The RAG Simulator lets you enter measurement results for a specific field and instantly see whether each assigned data quality rule would rate RED, AMBER, or GREEN. You can also adjust criticality ratings and bumper values to explore how the thresholds change before committing anything to the data.

Step 1 — Select a Critical Data Element

  1. 1
    Click RAG Simulator in the left sidebar.
  2. 2
    Use the four cascading dropdowns to locate the field you want to simulate:
    Select an Agency, then a Directorate, then a Data Set, then the Field (CDE). Each dropdown only becomes active once the previous one has a value.
  3. 3
    Once a field is selected, the panel below the dropdowns shows the CDE identity and its criticality ratings.
    The CDE identity shows the field name, source table, data set, and agency. The criticality panel shows one tile per criticality group (for example OPS, POL, REP, STRAT), each with its current level and score.
  4. 4
    To the right of the criticality tiles, the Overall score, Relative score, and RAG thresholds are calculated automatically from the current criticality levels.
    See How the RAG rating is calculated for a full explanation of how these numbers are derived.

Adjusting criticality for simulation

You can change any criticality level directly in the simulator to explore how the RAG thresholds would shift. The dropdown in each criticality tile lets you select a different level. Changed tiles are highlighted.

  1. 1
    Change one or more criticality level dropdowns in the tiles. The Overall score, Relative score, and RAG thresholds update immediately.
  2. 2
    If you want to keep the changes, click Apply (shown below the tiles when values differ from the stored ones). This saves the new levels back to the data permanently.
    If you want to discard the changes and return to the stored values, click Reset.
Applying criticality changes from the simulator has the same effect as editing the CDE from the Data and Stewardship page. The changes are saved to your working data and will be included in your next delta export.

Step 2 — Enter rule measurements

Once a CDE is selected, a measurement table appears showing all rules allocated to that field. Each row represents one rule allocation.

  1. 1
    For each rule row, enter the Sample size — the total number of records the rule checked (default 1,000).
  2. 2
    Enter the Failing records — the number of records that failed the check (default 1).
  3. 3
    The Pass rate and RAG columns update immediately. The row background tints green, amber, or red to match.
  4. 4
    A summary bar at the top of the table shows the total count of GREEN, AMBER, and RED rules across the simulation.

Understanding the measurement table columns

ColumnWhat it shows
RuleThe name of the data quality rule.
DimensionThe quality dimension measured by this allocation (for example, Completeness).
BumperA value from 1 to 5 that raises the GREEN threshold. Use the − and + buttons to adjust it. Bumper 1 means no adjustment; bumper 5 sets the GREEN threshold to 100%. See How the RAG rating is calculated.
ThresholdsThe calculated GREEN, AMBER, and RED pass-rate thresholds for this rule, taking the bumper into account.
Sample sizeEditable. The number of records checked by the rule run.
Failing recordsEditable. The number of records that did not pass the rule check.
Pass rateCalculated as (sample − failing) ÷ sample.
RAGGREEN if pass rate ≥ GREEN threshold; AMBER if ≥ AMBER threshold; RED otherwise.

Saving an adjusted bumper value

If you change a bumper value during the simulation and want to keep it, you can save it back to the rule allocation without leaving the simulator.

  1. 1
    Adjust the bumper using the − and + buttons on a rule row. When the value differs from the stored value, Apply and Reset buttons appear.
  2. 2
    Click Apply to save the new bumper to that rule allocation. A brief Saved confirmation appears. Click Reset to revert to the stored value without saving.
The simulator does not retain your measurement inputs between sessions. Sample size and failing count values reset when you navigate away or reload the page. Only criticality levels and bumper values saved with the Apply button are persisted.
