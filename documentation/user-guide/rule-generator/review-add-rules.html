How to review and add AI-suggested rules

After parsing the AI response, Step 3 displays one card per suggestion. Review each card, adjust the settings if needed, then add individual rules or all of them at once.

Two types of suggestion card

The AI can suggest either a completely new rule or that an existing rule from the catalogue already fits and should simply be allocated to this field.

Card typeWhat it meansWhat gets saved
New rule The AI has written a new SQL-based rule that does not yet exist in the catalogue. The card shows the rule name, quality dimension badge, business description, the profiling observation that triggered the suggestion, and a preview of the SQL. Clicking Add Rule and Allocate creates a new rule in the catalogue and allocates it to this field in one step.
Reuse Existing The AI found an equivalent rule already in the catalogue. The card shows a blue REUSE EXISTING badge, the existing rule name, and why the AI thinks it applies. Clicking Allocate Existing Rule creates only a new allocation linking the existing rule to this field. The rule itself is unchanged.

Conflict warnings

The application checks each suggestion against rules already allocated to this field and flags potential overlaps with an amber warning on the card:

WarningMeaning
Dimension already covered This field already has a rule allocated for the same quality dimension. Consider whether you need a second rule for the same dimension or whether you should skip this suggestion.
Duplicate rule exists A rule with the same name is already in the catalogue. The suggestion is redundant.
Similar rule exists A rule with a similar name is in the catalogue. Review whether the new rule genuinely adds something different before adding it.
Rule not found in catalogue Applies to REUSE suggestions only. The AI named a rule that does not exist in the catalogue. The Allocate button will be disabled. Dismiss this card or use the rule name to create it manually.

Adjusting a suggestion before adding it

  1. 1
    For a New rule card, the rule name is an editable text field. Correct the name if needed before adding — once added it cannot be changed from the generator.
  2. 2
    Use the Dimension dropdown to change the quality dimension if the AI's choice is wrong (options: Completeness, Validity, Uniqueness, Consistency, Timeliness, Accuracy).
  3. 3
    Use the inline RAG preview to test pass-rate thresholds before committing. Enter the total record count in Sample size and the count of records the rule would flag in Failing. The RAG badge (GREEN / AMBER / RED) updates instantly. The threshold legend below the inputs shows the pass-rate percentages required for Green and Amber, derived from the CDE's criticality scores. If no criticality is defined for the CDE, the preview shows a message instead of inputs. To adjust the underlying thresholds, use the RAG Simulator.

Testing the SQL before adding

Each card shows a preview of the SQL template. To copy the composed SQL ready for testing, use the Copy SQL button:

  1. 1
    Click Copy SQL on the card. The button copies a composed version of the SQL to the clipboard — with the field's database, table, and field name substituted into the placeholders, and the snapshot filter appended.
  2. 2
    Paste the SQL into Athena (or another query tool) and run it to verify it returns the expected count of failing records.
  3. 3
    If the SQL needs correction, do not add this suggestion. Add the rule manually from the Rules Explorer where you can edit the SQL directly. See How to add or edit a rule.

Adding rules

  1. 1
    Click Add Rule and Allocate (new rule) or Allocate Existing Rule (reuse suggestion) to add a single card. The card becomes faded and shows Added or Allocated to confirm.
  2. 2
    To add all remaining un-added suggestions at once, click Add all (X remaining) at the top of the Step 3 panel. This applies the current settings on each card without further prompts.
Added rules and allocations are saved to your working data immediately and are included in your next delta export. If you add a rule by mistake, go to the Rules Explorer to retire the rule or retire the allocation. See How to add or edit a rule and How to manage allocations from the Rules Explorer.

You do not need to add every suggestion. It is normal to accept some, skip others, and run the generator again on the same field after profiling data improves.
