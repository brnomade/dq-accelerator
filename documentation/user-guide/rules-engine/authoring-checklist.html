Rule authoring checklist

Run through this checklist before saving a rule in the DQ Accelerator. Each item maps to a requirement that the engine will enforce at run time.

Before saving a rule

  • SQL starts with SELECT — no leading comments, no CTE (WITH … AS). The very first characters must be SELECT.
  • Returns the correct output shape — automated rules must return a single numeric count. Manual rules must return exactly four columns: failures_count, total_sample_count, measurement_timestamp, extraction_timestamp.
  • Uses placeholders for the CDE's source identifiers — do not hardcode database or table names. Use {SOURCE_DATABASE_NAME}, {SOURCE_TABLE_NAME}, and {SOURCE_FIELD_NAME} where appropriate.
  • Contains no semicolons — not at the end of the statement, and not inside string literals (e.g. avoid 'call at 3;30pm').
  • Contains no DML or DDL keywords — INSERT, UPDATE, DELETE, MERGE, DROP, TRUNCATE, ALTER, and CREATE are all blocked as standalone tokens.
  • Has an outer WHERE clause if a snapshot filter is set on the CDE — the engine appends the filter as AND {filter}. Use WHERE 1=1 if no natural condition exists at the outer level.
  • $partitions references use the pre-quoted form — write "{SOURCE_TABLE_NAME}$partitions" (with quotes around the placeholder), not a bare {SOURCE_TABLE_NAME}$partitions.
  • Other table references use literal names — only the CDE's own source database and table should use placeholders. Reference tables, lookup tables, and any other joined tables should use their full literal names.
  • SQL has been tested in Athena — run the SQL (with placeholder values substituted manually) in the Athena console to confirm it executes and returns the expected count before saving.
