How to write SQL for automated rules

Automated rules require a SQL query that returns a single count of failing records. This page covers the required structure, placeholders, and common patterns.

Required structure

Your SQL must return a single numeric value — the count of records that fail the check. The engine wraps this count as the numerator of the quality measurement.

SELECT COUNT(*) FROM {SOURCE_DATABASE_NAME}.{SOURCE_TABLE_NAME} WHERE <your failure condition>

The engine automatically generates a second query for the denominator (total sample count) using the same table and any snapshot filter defined on the CDE.

Examples

Null check
SELECT COUNT(*) FROM {source_database_name}.{source_table_name} WHERE {source_field_name} IS NULL
Future date check
SELECT COUNT(*) FROM {source_database_name}.{source_table_name} WHERE DATE({source_field_name}) > CURRENT_DATE
Negative value check
SELECT COUNT(*) FROM {source_database_name}.{source_table_name} WHERE CAST({source_field_name} AS DOUBLE) < 0
Allowed-values check
SELECT COUNT(*) FROM {source_database_name}.{source_table_name} WHERE {source_field_name} NOT IN ('North', 'South', 'East', 'West')

Placeholders

These three placeholders are replaced at run time with values from the linked CDE. They are case-insensitive — {source_table_name} and {SOURCE_TABLE_NAME} both work — but must be consistently cased within a single placeholder (not {Source_Table_Name}).

PlaceholderReplaced withOutput format
{SOURCE_DATABASE_NAME} CDE source_database_name "my_database" (double-quoted)
{SOURCE_TABLE_NAME} CDE source_table_name "my_table" (double-quoted)
{SOURCE_FIELD_NAME} CDE source_field_name "my_column" (double-quoted)
The engine adds double-quotes automatically. Both bare ({SOURCE_TABLE_NAME}) and pre-quoted ("{SOURCE_TABLE_NAME}") placeholders are handled correctly. Double-quoting means reserved words and mixed-case names are handled safely by Athena.

$partitions references

When referencing Hive partition metadata, the $partitions suffix must sit inside the quoted identifier. Both of these input patterns are handled correctly by the engine:

  • "{SOURCE_TABLE_NAME}$partitions" → "my_table$partitions"
  • {SOURCE_TABLE_NAME}$partitions → "my_table$partitions"
SELECT MAX(glueexporteddate) FROM {SOURCE_DATABASE_NAME}."{SOURCE_TABLE_NAME}$partitions"

Referencing other tables

If your rule joins to tables other than the CDE's source table, write those database and table names directly in the SQL. Do not use placeholders for tables that are not the CDE's source.

SELECT COUNT(*) FROM {SOURCE_DATABASE_NAME}.{SOURCE_TABLE_NAME} WHERE {SOURCE_FIELD_NAME} NOT IN ( SELECT DISTINCT status_code FROM my_other_database.reference_table )

Snapshot filter requirement

If your CDE has a source_snapshot_filter defined, the engine appends it to your SQL as AND {filter}. This means your SQL must always end with an outer WHERE clause at the outermost query level.

If your SQL does not have an outer WHERE clause, the injected filter produces invalid SQL. Use WHERE 1=1 as a safe placeholder when no natural condition exists at the outer level.
This will break — no outer WHERE for the filter to attach to
SELECT COUNT(*) FROM ( SELECT * FROM {SOURCE_DATABASE_NAME}.{SOURCE_TABLE_NAME} WHERE status = 'active' )
This works — WHERE 1=1 gives the AND somewhere to attach
SELECT COUNT(*) FROM ( SELECT * FROM {SOURCE_DATABASE_NAME}.{SOURCE_TABLE_NAME} WHERE status = 'active' ) WHERE 1=1
The snapshot filter is applied before placeholder substitution. You can use {SOURCE_DATABASE_NAME} and {SOURCE_TABLE_NAME} inside the filter value itself — they will be substituted at the same time as the placeholders in the rule SQL.
