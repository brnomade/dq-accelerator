How to allocate a rule to a CDE

A rule allocation is the link between a rule and a CDE. It tells the engine which rule to run against which table, and how often. A rule does not run until it has at least one active allocation.

Allocation field reference

FieldRequiredDescription
data_quality_rule_allocation_id required Unique identifier for this allocation.
data_quality_rule_id required The rule to run. Must reference an active rule in the Data Quality Rule table.
critical_data_element_id required The CDE to run the rule against. The engine uses the CDE's source database, table, field, and snapshot filter to build the SQL.
frequency required How often the engine runs this allocation. Must be one of: hourly, daily, weekly, ad-hoc. See schedule values below.
retiring_timestamp optional Set to a past timestamp to deactivate this allocation without deleting it. Leave blank to keep the allocation active.

Schedule values

ValueRule typeWhen it runs
hourly Automated Every hour. Can be combined with daily and weekly in the same run.
daily Automated Once per day. Can be combined with hourly and weekly in the same run.
weekly Automated Once per week. Can be combined with hourly and daily in the same run.
ad-hoc Manual Only when manually triggered. Cannot be combined with automated schedules in the same run. Use this for all manual rules.
ad-hoc and automated schedules cannot run together. If a run includes ad-hoc alongside hourly, daily, or weekly, the engine will reject the run before processing any rules. Trigger ad-hoc runs separately.

One rule, many CDEs

The same rule can be allocated to multiple CDEs. Each allocation is independent — the engine runs the rule once per allocation, substituting the CDE's source database, table, and field each time. This is how a generic rule such as a null check can be applied across many different columns without duplicating the SQL.

Retiring an allocation

Setting a retiring_timestamp on an allocation deactivates it for future runs while preserving the historical measurement record. The rule and CDE remain active and can be re-allocated at any time.

If the CDE or the rule itself is retired, the allocation is effectively inactive even if its own retiring_timestamp is blank.
