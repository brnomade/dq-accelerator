How to add or edit a rule

Data quality rules are managed from the Rules Explorer. Each rule defines the SQL logic used to check a data field. Once added, a rule can be assigned to one or more CDEs from the Data and Stewardship page.

Add a rule

  1. 1
    Click Rules Explorer in the left sidebar.
  2. 2
    Click the Add rule button in the top-right of the page.
    The button is disabled if your steward identity is not set. See How to set your steward identity.
  3. 3
    Fill in the rule form panel that slides open. Required fields are marked with a red asterisk.
    See the field reference below.
  4. 4
    Click Add. The new rule appears in the list immediately, sorted alphabetically by name.

Edit a rule

  1. 1
    Find the rule in the list. Use the search box to locate it quickly.
  2. 2
    Click the pencil icon on the right side of the rule row. The Edit Rule panel slides open with all current values pre-filled.
  3. 3
    Update any fields and click Save. Changes take effect immediately.

Retire and restore a rule

Retiring a rule marks it as inactive. Existing allocations that reference it are not deleted but become inactive alongside it.

  1. 1
    Click the eye-off icon on the rule row to retire it immediately. There is no confirmation prompt.
  2. 2
    To restore a retired rule, enable the Show retired toggle in the toolbar (appears when retired rules exist), then click the eye icon on the retired rule row.

Field reference

FieldNotes
Name required The rule name. Displayed throughout the application and in exports. Use a consistent naming convention so rules sort predictably (for example, Generic - Null check or CDS_NAME - Specific check).
Explanation optional A plain-language description of what the rule checks. Shown as a subtitle on the rule row.
SQL code required The SQL template for this rule. Must contain a SELECT statement. Tokens such as {table}, {field}, and {snapshot} are substituted at runtime when the SQL is composed for a specific CDE. See How to view rule SQL for details on token substitution.
SQL sample optional An alternative SQL template used to generate a row-level sample alongside the aggregate check. If left blank, the application falls back to a default sampling approach (shown as a DEF badge in the allocation row).
Source link optional A URL or reference pointing to the rule definition in an external system (for example, a Confluence page or a code repository).
Automated optional Toggle on if this rule is run by an automated pipeline. An AUTOMATED badge appears on the rule row when enabled.
Changing a rule's SQL code affects every CDE it is already allocated to. The next time the composed SQL is viewed or exported, it will use the updated template.
